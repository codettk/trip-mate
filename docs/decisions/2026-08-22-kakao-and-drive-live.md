# 카카오·구글 드라이브를 실제로 붙였다

2026-08-22 · 목(mock)이 아니라 실제 자격증명으로 왕복시켰다. 통과한 것과, 통과하면서 드러난 구멍 셋.

## 카카오 — 끝났다

`AUTH_MODE=kakao`. 시크릿이 맞는지 토큰 엔드포인트에 직접 물어서 확인했다.

```
시크릿 있음   400 KOE320  authorization code not found   ← 클라이언트 인증은 통과
시크릿 없음   401 KOE010  Bad client credentials
```

`KOE320`(코드가 가짜라서 나는 오류)까지 갔다는 건 **클라이언트 인증을 통과했다**는 뜻이다.
인가 URL 도 카카오가 302 로 로그인 화면에 넘긴다. `AUTH_MODE=kakao` 에서 `POST /api/auth/mock` 은 401 이다.

> 새 REST API 키는 **클라이언트 시크릿이 켜진 채로 생성된다.** 예전 문서를 보고 시크릿 없이
> 붙이면 `KOE010` 만 나오고 원인이 안 보인다. 시크릿은 콘솔의
> `앱 설정 → 플랫폼 키 → REST API 키 → 클라이언트 시크릿` 에 있다.

## 드라이브 — 전송된다

어댑터 직접(13건)과 API 왕복(15건) 둘 다 통과. 200KB JPEG 을 올렸다 받아 **바이트가 그대로**였다.

```
루트 폴더 생성 → drive_folder_id 1C3M-Nb…      모임 제목 = 폴더 이름
업로드         → storage_key   1Bc-oYL…        실제 Drive fileId
GET /api/media/{id} 200, 200,022 = 200,022 바이트, SHA-256 일치
모임 이름 변경 → 폴더 이름 따라감, folderId 그대로
응답 어디에도 drive.google.com / webViewLink / 서명 URL 없음
```

`upload()` 가 돌려주는 필드는 `key,size` 뿐이다. **Drive 링크가 밖으로 나갈 통로 자체가 없다.**

## 구멍 1 — 구글 프로젝트를 다른 서비스와 같이 쓰고 있다

`config/google_client_secret.json` 은 프로젝트 `shared-media-502314` 것이고, 사용자가 **다른 프로젝트(CMS)에서
이미 쓰고 있는** 클라이언트다. 이 토큰으로 Drive 를 조회하니 그쪽 파일이 그대로 보인다 —
`_cms`, `shared-media`, `*_proxy.mp4`, `*_thumb.jpg`, 개인 사진 폴더까지.

`drive.file` 은 "앱이 만든 파일만"이라 안전해 보이지만, **여기서 '앱'이 두 서비스를 함께 가리킨다.**
TripMate 는 지금 `files.list` 를 부르지 않고 항상 `parents` 를 명시해 만들기만 하므로 실제 유출은 없다.
그러나 나중에 누가 "고아 파일 정리" 같은 걸 짜면서 목록을 한 번 부르는 순간 남의 파일이 딸려 온다.

**TripMate 전용 Google Cloud 프로젝트를 따로 만들 것.** 클라이언트만 새로 만드는 게 아니라 프로젝트를 나눈다 —
브랜딩·게시 상태·할당량이 CMS 와 얽히지 않게 한다.
**되돌리는 비용:** `.env` 의 `GOOGLE_CLIENT_ID/SECRET/REFRESH_TOKEN` 세 줄. 코드는 안 바뀐다.

## 구멍 2 — 게시하려면 URL 두 개가 필요하다

`drive.file` 은 **민감하지 않은 스코프**라 심사(verification)는 면제된다. 하지만 **게시 자체**는 별개다.
콘솔이 그대로 말한다.

> 앱을 외부 프로덕션 모드로 전환하려면 유효한 앱 이름, 지원 이메일, **홈페이지 URL, 개인정보처리방침 URL**이 필요합니다.

| | 테스트 중 (지금) | 프로덕션 |
|---|---|---|
| 업로드·다운로드 | 된다 | 된다 |
| 쓸 수 있는 사람 | 테스트 사용자 100명 | 누구나 |
| **리프레시 토큰 수명** | **7일** | 무기한 |
| 필요한 것 | 없음 | 홈페이지 URL + 개인정보처리방침 URL |

`CLAUDE.md` 의 "아직 안 정한 것"에 **호스팅과 도메인**이 남아 있어서 지금 넣을 URL 이 없다.
그래서 **테스트 중으로 두고 7일마다 재승인**한다. 도메인이 정해지면 URL 두 개 넣고 게시한다.

7일 만료가 개발 중에도 계속 걸리적거리므로, 도메인 결정을 기다리지 않고 무료 정적 페이지
(GitHub Pages 등)로 URL 두 개를 먼저 만들어 게시해 버리는 선택지도 있다. 나중에 진짜 도메인이 생기면
URL 만 바꿔 끼우면 된다. **사용자 결정 대기 중.**

## 구멍 3 — local → gdrive 전환에 마이그레이션이 없다

`STORAGE_DRIVER` 는 전역 스위치인데 `photos.storage_key` 는 드라이버마다 형식이 다르다
(local 은 `{folderUuid}/{fileUuid}`, gdrive 는 Drive fileId). 그래서 **드라이버를 바꾸면 이미 올라간 사진이 전부 404 다.**

실제로 확인했다 — gdrive 로 바꾼 상태에서 기존 로컬 사진(`일출봉.png`)이 `GET /api/media/…` 에 **404**.
데이터가 사라지는 건 아니고 되돌리면 다시 보이지만, **조용히 깨진다**는 게 문제다.

지금은 개발 DB에 로컬 사진이 2장뿐이라 **`STORAGE_DRIVER=local` 로 되돌려 뒀다.**
실제로 gdrive 로 넘어갈 때 필요한 것:

1. `photos.storage_driver` 컬럼을 추가해 행마다 어디에 있는지 기록하거나,
2. 전환 시점에 로컬 파일을 Drive 로 올려 `storage_key` 를 갈아 끼우는 일회성 스크립트를 쓰거나,
3. 전환 전 사진이 없음을 확인하고 그냥 넘어간다.

**3번이면 지금 당장은 충분하다** — 실서비스 데이터가 아직 없다. 다만 **그때 확인하지 않으면 조용히 깨진다.**
1번이 정석이고 마이그레이션 한 건이면 된다.

## 추가 — 최상위 폴더를 사용자가 지정했다 (같은 날 오후)

사용자가 Drive 에서 직접 만든 폴더 하나를 최상위로 쓰겠다고 했다.
`drive.file` 은 "앱이 만든 파일만"이라 **안 될 것 같았지만, 시켜 보니 됐다.**

```
files.get(그 폴더)                     404 File not found
files.create(parents=[그 폴더])        OK   parents=["14s1BIk…"]
그 안에 하위 폴더                       OK
그 안에 파일 업로드                     OK
```

**읽지는 못하지만 그 안에 만드는 것은 된다.** `GoogleDriveAdapter.root()` 가 오직
`createFolder` 의 `parents:` 값으로만 쓰이고 어디서도 읽지 않기 때문에 그대로 맞아떨어졌다.

`GOOGLE_DRIVE_ROOT_FOLDER_ID` 를 채웠고, 모임 폴더가 그 바로 밑에 생기는 것을 확인했다.

```
14s1BIk… (사용자가 만든 폴더)
  └─ 제주도 4박 5일/          ← 모임 폴더 이름 = 모임 제목
       ├─ Day 1 · 성산/
       ├─ 일출봉/
       └─ …
```

폴더 이름은 **모임 제목 그대로 둔다.** 사용자가 "UUID 여도 된다"고 했지만
`Group.name` 과 루트 `Folder.name` 이 항상 같다는 건 확정된 규칙이고,
Drive 를 직접 열었을 때 어느 모임인지 보이는 편이 낫다. 되돌리는 비용은 `createFolder` 호출 한 줄이다.

> ⚠ **`files.list` 를 넣지 말 것.** `drive.file` 의 목록은 같은 OAuth 클라이언트로 만든
> 다른 앱의 파일까지 함께 돌려준다 (구멍 1). 지금은 항상 `parents` 를 명시해 만들기만 하므로
> 남의 파일에 닿을 통로가 아예 없다. 목록을 한 번 부르는 순간 그 보호가 사라진다.

### 구멍 3 은 닫았다

`STORAGE_DRIVER=gdrive` 로 넘기면서 기존 폴더 12개를 Drive 로 이관했다
(`.data/tmp/migrate-local-to-drive.mjs`, 백업 `.data/tmp/migrate-backup.json`).
부모부터 만들어 계층을 그대로 옮겼고, 로컬 파일은 지우지 않았다.

이관 중에 알게 된 것: **`.data/storage` 에 실제 파일이 하나도 없었다.**
「제주도 4박 5일」의 사진 2장(`일출봉.png`, `영수증.png`)은 DB 행만 있고 바이트가 없는 상태였다 —
`local` 에서도 이미 404 였다는 뜻이다. 이관이 깨뜨린 게 아니다. **그 2행은 그대로 뒀다.**

### 구멍 2 는 열려 있다 — 도메인은 있다

사용자가 도메인을 이미 갖고 있고 서브도메인만 만들면 된다고 했다. 서브도메인이 정해지면 필요한 것:

| 어디 | 무엇 |
|---|---|
| Google 브랜딩 | 홈페이지 URL · 개인정보처리방침 URL → 게시하면 7일 만료가 사라진다 |
| 카카오 콘솔 | Redirect URI 에 `https://<서브도메인>/api/auth/kakao/callback` 추가 |
| `.env` | `APP_ORIGIN` · `KAKAO_REDIRECT_URI` · `VITE_API_BASE` |

그때까지는 테스트 중 상태이고 리프레시 토큰이 7일마다 만료된다.
