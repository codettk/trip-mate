# TripMate 모호성 해소 — 확정 결정 (2026-08-17)

기획 검토에서 나온 **모호한 지점 21개에 대한 사용자 답변**과, 거기서 도출한 확정 규칙이다.
이 문서는 그대로 **작업 지시 프롬프트로 쓸 수 있게** 쓰였다. 항목 번호는 검토 당시 번호를 유지한다.

> 이 문서의 「확정」은 `CLAUDE.md`의 "확정된 결정"과 같은 무게를 가진다.
> 바꾸려면 사용자 승인이 필요하다.

## 1. 저장소 소유권

**사용자 원문**
> 내 드라이브 5TB가 있기 때문에 이게 우리 시스템의 스토리지야.

**확정**
- TripMate의 파일 저장소는 **운영자 본인의 Google Drive 계정 한 곳**이다. 멤버 개인의 Drive를 쓰지 않는다.
- 따라서 **모임 생성자가 탈퇴해도 사진은 사라지지 않는다.** 소유자는 언제나 서비스다.
- 멤버는 Drive 계정을 연결하지 않는다. 멤버에게 요구하는 인증은 카카오 로그인뿐이다.
- 모든 모임의 루트 폴더는 이 계정의 같은 상위 폴더 아래에 나란히 생긴다.

**구현 지시**
- DB에는 `driveFolderId` / `driveFileId`만 저장한다. 바이너리를 자체 저장하지 않는다.
- 용량 한도(5TB)는 서비스 전체 공용이다. 설정 화면의 사용량 표시는 **모임별이 아니라 서비스 전체** 기준임을 문구로 밝힌다.

## 2. 뷰어 링크 주소 체계

**사용자 원문**
> 뷰어 링크의 경우에는 그냥 우리 시스템의 URL을 기준으로, 모임의 고유 ID 뒤에 view/foler_name 이런식으로 하면 해당 뷰어 폴더만 보이게 하면 될듯.

**확정**
```
tripmate.app/{groupId}/view/{folderSlug}
```
- 예: `tripmate.app/g1/view/day1-seongsan`
- 이 주소는 **그 폴더의 미디어만** 보여 준다. 하위 폴더·형제 폴더로 이동 불가, 업로드·삭제 불가.
- 이미지 자체도 TripMate URL로 나간다. **Drive 파일 링크나 서명 URL을 브라우저에 노출하지 않는다** — 서버가 Drive에서 받아 전달한다.

**구현 지시**
- `Folder`에 `slug`를 둔다. 같은 모임 안에서 유일해야 한다. 폴더 이름을 바꾸면 slug도 바뀌고, **이전 링크는 죽는다** (이게 정상 동작이다).
- 뷰어 페이지는 로그인을 요구하지 않는다.

## 3. Google 자격증명

**사용자 원문**
> 해당 내용은 구글 클라이언트 시크릿 토큰을 활용할 예정이야.

**확정**
- **OAuth 클라이언트 시크릿 + 리프레시 토큰** 방식. 서비스 계정 키가 아니다.
- 토큰 주체는 1번의 운영자 계정 하나다. 멤버별 OAuth 동의는 없다.
- 이전에 "API 키만 있으면 된다"고 정리했던 항목은 **폐기**한다 — API 키로는 업로드가 되지 않는다.

**구현 지시**
- 클라이언트 시크릿과 리프레시 토큰은 서버 환경변수로만 둔다. 프런트로 내려보내지 않는다.
- 업로드·다운로드·폴더 생성/리네임은 전부 서버를 통한다.

## 4. 폴더 공개/비공개

**사용자 원문**
> 공개/비공개 기능이 있어야돼.

**확정**
- 폴더마다 공개/비공개 토글을 둔다. 기본값은 **비공개**.
- 비공개로 되돌리면 **그 링크는 즉시 죽는다.**
- 다시 공개하면 **새 토큰이 발급된다** — 예전에 뿌린 링크는 되살아나지 않는다.

**구현 지시**
- 링크를 폴더 ID에서 파생시키지 말 것. 공개할 때마다 새 토큰을 만들어 저장한다.
- 화면에 "이전에 공유한 링크는 더 이상 열리지 않습니다"라고 알린다.

## 5. 문서 공유 없음

**사용자 원문**
> 문서의 외부 공개 범위는 필요없어. 사진/동영상의 미디어만 공유가능해.

**확정**
- 외부로 나가는 것은 **미디어(사진·동영상)뿐**이다.
- 문서는 **모임 멤버 전용**이다. `Doc.pub`을 없앤다.
- 예외는 21번의 정산 공유 링크 하나뿐이다 (정산 결과 뷰어).

## 6. 초대 링크

**사용자 원문**
> 초대 링크의 승인은 필요없어. 그냥 모임을 만든 사람이 방장이고, url을 공유해주면 30분 동안 유효한 초대 링크야. 그안에만 들어오면 아무나 모임에 들어올 수 있어.

**확정**
- 모임을 만든 사람이 **방장**이다.
- 초대 링크는 **발급 후 30분** 유효하다. 그 안에 들어오면 **승인 없이 즉시 멤버**가 된다.
- 만료되면 방장이 다시 발급한다. 발급하면 이전 링크는 죽는다.

**구현 지시**
- 초대 모달에 **남은 시간 카운트다운**과 "다시 발급" 버튼을 둔다.
- 만료된 링크로 들어오면 "링크가 만료되었습니다 — 방장에게 새 링크를 요청하세요"를 보여 준다.

## 7. 모임 스위처 위치

**사용자 원문**
> 스위처 위치는 너가 판단해줘.

**확정 — 사이드바 하단 유지**
- 모임 전환은 하루에 몇 번 하는 동작이 아니다. 상단(가장 눈에 띄는 자리)은 지금 보고 있는 모임의 이름과 날짜에 준다.
- 계정 칩 바로 위에 두면 "계정 → 모임 → 화면"으로 범위가 좁아지는 순서가 되어 읽기 쉽다.
- 메모리 `trip-mate-group-model.md`에 "상단"으로 적혀 있던 기술은 **오기**이므로 고친다.

## 8. 반올림 설정 제거

**사용자 원문**
> 설정의 10원, 100원 단위라는 내용은 없애주고, 그냥 원단위로 쪼개는 시스템 설정으로 그냥 하드코딩할거야.

**확정**
- 반올림 단위는 **원 단위 고정**. 사용자 설정으로 노출하지 않는다.
- `per = round(cost / 인원)`, 남는 1~2원은 결제자가 흡수한다. (기존 규칙 그대로)

## 9. 미디어 정렬

**사용자 원문**
> 우리에게 정렬은 업로드한 시간을 기준으로 기본 정렬을 보여줄거야. 추가적으로 정렬 기능에는 업로드 순/촬영순 으로 할거고, 촬영 시간 메타데이터가 없다면 해당 미디어는 업로드 시간을 기준으로 믿을거야.

**확정**
- 기본 정렬: **업로드 시각 순**.
- 선택 정렬: **촬영 시각 순**. EXIF 촬영 시각이 없는 미디어는 **업로드 시각을 촬영 시각으로 간주**한다.
- 앱이 촬영 시각으로 **폴더를 자동 분류하지는 않는다** — 정렬에만 쓴다. (기존 규칙 유지)

**구현 지시**
- `Photo { driveFileId, name, folderId, uploadedAt, takenAt|null }`. `uploadedAt`은 필수.
- 촬영순 정렬 시, 메타데이터가 없어 대체된 항목이 몇 개인지 화면에 알린다.

## 10. `booked` / `note` 정리 (사용자 답변 없음 — 담당자 판단)

**확정**
- `Item.booked`(예약 완료)는 데이터에만 있고 입력 UI가 없었다. → **일정 폼에 체크박스로 노출**한다.
- `Item.note`는 `Item.meta`(메모)와 역할이 겹치고 어디에도 표시되지 않았다. → **삭제**하고 `meta` 하나로 간다.

## 11. 정산 대상 지정

**사용자 원문**
> 우리는 실제로 혼자 결제한 사람도 있을 수 있기 때문에 특정 인원에게만 n/1 계산을 적용할거야.

**확정**
- 기존 `shared:{members[], guests}` 모델을 그대로 유지한다. 전원 균등은 기본값일 뿐이다.
- **파생 규칙:** "전원 균등"을 가정한 숫자를 화면에 쓰지 않는다.
  - `총액 ÷ 전체 멤버 수`로 계산한 **"1인당 평균 / 1인당 부담액" 표기를 없앤다.** 항목마다 대상이 다르면 아무도 실제로 부담하지 않는 금액이라 오해를 만든다.
  - 대신 **"내 부담액"(로그인한 사람의 `owed`)** 을 보여 준다.

## 12. 정산 여부 토글

**사용자 원문**
> 정산 대상이 0명인 경우, 즉 정산이 아니라 일정만 추가하는 경우가 있기 때문에 정산이라는 것을 드롭다운에 넣지 말고, 정산 여부를 클릭하게 해서 정산이 활성화 되면 금액과 대상자를 선택할 수 있게 하자.

**확정**
- `Item`에 **`split`(정산 포함 여부)** 을 신설한다. 기본값은 **꺼짐**.
- 꺼져 있으면 폼에서 **금액·통화·결제자·정산 대상 입력 자체가 보이지 않는다.**
- 저장 시 꺼져 있으면 `cost:0, payer:null, shared:{members:[],guests:0}`으로 확정 저장한다. 숨겨진 금액을 남기지 않는다.
- 일정 카드와 정산 장부에는 "정산 제외"로 표시한다. **조용히 사라지지 않는다.**

## 13. 1~2원 차이 설명

**사용자 원문**
> 총결제를 기준으로 1~2원 다를 수 있는 부분은 잘 설명하면 되니까 내용으로 설명해줘.

**확정 — 두 숫자를 분리해서 이름을 다르게 붙인다**

| 이름 | 뜻 | 계산 |
|---|---|---|
| **실제 결제액** | 그 사람이 실제로 긁거나 낸 돈 | `Σ item.krw` (payer 기준) |
| **정산 반영액** | 정산 계산에 들어간 금액 | `Σ (per × 대상 인원수)` |

- 두 값은 반올림 때문에 항목당 1~2원 차이가 날 수 있다.
- 화면에는 **실제 결제액을 크게**, 정산 반영액은 필요한 자리에서만 쓴다.
- 문구: "1인 몫을 원 단위로 반올림하면서 생긴 1~2원은 결제자가 부담합니다. 그래서 실제 결제액과 정산 반영액이 조금 다를 수 있습니다."

## 14. 수령 확인 = 정산 완료

**사용자 원문**
> 돈을 받는다는 기준을 시스템이 하지 않을거고, 사용자가 정산 완료 버튼을 눌러서 직접 자기가 받았다는 내용을 표기해줄거야.

**확정**
- 입금 여부를 시스템이 판단하지 않는다. **돈을 받은 사람이 "정산 완료"를 눌러야** 그 건이 끝난다.
- 기타 인원 몫(모임 밖 사람에게 직접 받는 돈)도 같은 방식으로 **결제자가 "받음 확인"** 을 누른다.

## 15. 송금 확인 요청

**사용자 원문**
> 정산 마감은 14번을 기준으로 할거고, 송금 완료는 내가 정산 대상자라면 내가 입금하고 송금 확인 요청 버튼 누르면 될 거 같아.

**확정 — 이체 한 건의 상태 3단계**

```
대기  ──[보낸 사람: 송금 확인 요청]──▶  확인 대기  ──[받는 사람: 정산 완료]──▶  완료
```
- 모든 이체가 **완료**되고 기타 인원 몫까지 확인되면 그 모임의 정산이 **마감**된다.
- 마감 후 정산에 영향을 주는 항목을 고치면 **경고**한다 (재계산은 하되 마감을 풀고 알린다).

**구현 지시**
- 이체는 계산으로 도출되므로 상태는 `{from, to}` 키로 따로 저장한다.
- 버튼은 **로그인한 사람에게 해당하는 것만** 활성화한다. 남의 이체를 대신 완료 처리할 수 없다.

## 16. 나간 멤버

**사용자 원문**
> 멤버가 모임에서 나가더라도 정산에서는 이미 존재하기 때문에 우리에게는 기타로 보여지면 될 거 같아.

**확정**
- 멤버가 나가도 **정산에서 지우지 않는다.** 이미 낸 돈과 낼 돈이 그대로 남는다.
- 나간 멤버는 화면에서 **"기타"로 표시**한다 (회색 아바타 + 이름 뒤 "나감").
- 나간 멤버는 새 지출의 **정산 대상 기본값에서 빠지고**, 멤버 목록·초대 화면에도 나오지 않는다.

**구현 지시**
- `Member.left`를 신설한다. `ACTIVE = MEMBERS.filter(m => !m.left)`.
- 아바타 스택, 새 항목의 `shared` 기본값, 멤버 카드 = `ACTIVE` 기준.
- 정산 계산·잔액표·이체 목록 = **`MEMBERS` 전체** 기준. (여기서 빼면 잔액 합이 0이 되지 않는다)

## 17. 모임 생성 항목

**사용자 원문**
> 여행 기간은 모임 생성시에 제목, 여행지, 시작, 종료, 메모 정도 넣었으면 좋겠어.

**확정 — 모임 생성 폼**

| 필드 | 필수 | 비고 |
|---|---|---|
| 제목 | ✅ | **Drive 루트 폴더 이름이 된다** |
| 여행지 | ✅ | 19번의 기본 통화를 여기서 정한다 |
| 시작일 | ✅ | 일차 자동 생성 시작점 |
| 종료일 | ✅ | 시작일 이상 |
| 메모 | — | 자유 텍스트 |

- 일차(`Day`)는 시작~종료에서 **자동 생성**된다. 사용자가 일차를 직접 추가·삭제하지 않는다.
- 기간을 나중에 늘리면 일차가 추가되고, 줄이면 **잘려 나가는 일차에 항목이 있을 때 경고**한다.

## 18. 숙소 기간

**사용자 원문**
> 숙소는 이름 별로 기간을 지정할 수 있어야돼. 특정 일자에는 숙소가 2개가 있을 수도 있어. 다른 지역에서 타 지역으로 이동한 후 체크인이 가능하니까.

**확정**
- `cat === "stay"`인 항목은 **체크인·체크아웃 날짜**를 갖는다. 박 수는 자동 계산된다.
- **하루에 숙소가 2개 이상일 수 있다.** 체크아웃하는 숙소와 체크인하는 숙소가 같은 날 겹치는 것은 정상이다.
- 숙소 카드는 **체크인 날**에 놓이고, 그 사이 날짜에는 "숙박 중"으로 표시된다.

**구현 지시**
- `Item`에 `checkIn`, `checkOut`을 추가한다 (stay 전용). 폼에서 `cat`이 숙소일 때만 노출한다.
- 일차 헤더에 그날 묵는 숙소를 표시한다. 2개면 2개 다 보여 준다.
- 숙소 비용은 **체크인 날 한 번만** 정산에 들어간다. 박 수로 쪼개지 않는다.

## 19. 통화와 환율

**사용자 원문**
> 통화는 각 지역별로의 화폐 단위를 정산에서 지정할 수 있게 해줘. 기본적으로는 모임의 지역을 기준으로 판단해서 자동 선택되면 좋고, 선택기능에서는 달러/페소/동 등 전세계 화폐 단위를 선택할 수 있게 해줘야돼. 그리고 통화를 기준으로 한국 금액은 해당 일자의 최종 환율을 기준으로 계산하면돼.

**확정**
- 지출은 **결제한 통화 그대로** 입력한다. `Item.cur`을 둔다.
- 기본 통화는 **모임의 여행지에서 자동 추론**한다 (제주 → KRW, 다낭 → VND, 후쿠오카 → JPY …). 항목마다 바꿀 수 있다.
- 원화 환산은 **그 항목이 속한 일자의 최종(마감) 환율**로 한다. 다른 날 같은 금액이라도 환산액이 다를 수 있다.
- **정산 계산과 이체 금액은 전부 원화 정수**로 한다. 외화는 표시용이다.

**구현 지시**
- 일자별 환율표를 저장한다: `rate[date][currency] = 1외화당 원`.
- 환율은 **항목을 저장하는 시점의 그 날짜 환율을 스냅샷**으로 함께 저장한다. 나중에 환율표가 갱신돼도 이미 정산된 금액이 흔들리면 안 된다.
- 화면에는 `$120.00` 옆에 `≈ ₩ 166,140` 형태로 병기하고, 어느 날 환율인지 밝힌다.
- 소수점은 **외화 입력에만** 허용한다. 원화 환산 결과와 정산 금액에는 절대 나오지 않는다.

## 20. 신규 사용자 온보딩

**사용자 원문**
> 신규 사용자의 경우에는 로그인 후, 모임 생성하기/모임 참여하기(url 복사) 기능을 넣어주면돼. 만약, url을 입력하고 들어왔다면 파라메터로 넘겨서 자동으로 모임에 들어가도록 "xx 모임에 참여하시겠습니까?"에서 확인 누르면 자동 모임 참여하면돼.

**확정**
- 모임이 하나도 없는 사용자는 로그인 직후 **"모임 만들기 / 모임 참여하기"** 두 갈래 화면을 본다.
- 모임 참여하기는 **초대 URL을 붙여 넣는** 방식이다.
- 초대 URL로 직접 들어온 경우 파라미터를 읽어 **"○○ 모임에 참여하시겠습니까?"** 확인을 띄우고, 확인하면 바로 합류한다.
- 링크가 만료(6번, 30분)됐으면 참여 대신 만료 안내를 띄운다.

## 21. 정산 내역 공유

**사용자 원문**
> 정산 내역 공유하기는 지금은 링크만 공유하면 될 거 같아. 링크 공유 시, 모임에 들어있다면 정산 페이지로 가면 되고, 비로그인 혹은 기타 사용자는 뷰어 페이지로 접근하면 돼.

**확정**
```
tripmate.app/{groupId}/settle/{token}
```
- 링크를 연 사람이 **그 모임의 멤버면** → 앱의 정산 화면으로 보낸다 (수정 가능).
- **비로그인이거나 멤버가 아니면** → 읽기 전용 정산 뷰어를 보여 준다.
- 뷰어에는 **이름·금액·이체 목록만** 나온다. 사진·문서·일정 상세로 넘어갈 수 없다.
- 5번의 "미디어만 외부 공유" 원칙의 **유일한 예외**다. 기타 인원에게 돈을 청구하려면 필요하기 때문이다.
