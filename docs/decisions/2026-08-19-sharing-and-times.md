# 공유 묶음과 종료 시각 (2026-08-19)

사용자가 실제로 써 보고 8건 + 1건을 지적했다. 그중 **확정 규칙 두 개를 뒤집는 요청**이
있어서, 무엇을 왜 바꾸는지와 되돌리는 비용을 여기 남긴다.

원 지적은 아래 아홉 가지다.

1. 여러 날에 걸친 숙소가 1일차에만 보인다
2. 시작 시각만 있고 종료 시각을 지정할 수 없다
3. 올린 미디어의 메타데이터·폴더를 고칠 수 없다
4. 폴더로 미디어를 가져오는 기능이 없다
5. 문서에 저장 버튼이 없다
6. 설정에서 기본 통화를 고칠 수 없다
7. 멤버가 폴더 공유 링크를 열어도 뷰어가 나온다 / 뷰어에서 빠져나갈 길이 없다
8. 모임 스위처에 URL 참여가 없다
9. 공유 범위를 폴더 하나로만 고를 수 있다 (최상위·부분집합 불가)

---

## 먼저, 1번은 버그가 아니었다

API 를 직접 호출해 확인했다. 5일 전부 숙소 칩이 내려오고 있었다.

```
1  2026-08-22  stays=["숙소:체크인"]
2  2026-08-23  stays=["숙소:숙박 중"]
3  2026-08-24  stays=["숙소:숙박 중"]
4  2026-08-25  stays=["숙소:숙박 중"]
5  2026-08-26  stays=["숙소:체크아웃"]
```

칩이 `font-size:11.5px` 짜리 작은 알약이라 눈에 띄지 않은 것이었다.
**칩을 키우고 "3박째"를 넣는 쪽으로 고친다.** 일정 카드를 매일 복제하지 않는다 —
같은 항목이 5번 있는 것처럼 보여 일정 개수와 금액 합계가 전부 어긋난다.

같은 이유로 5번도 절반은 오해였다. 문서는 **이미 자동 저장되고 있었다**
(600ms 디바운스 + blur 즉시 반영). 저장됐다는 신호가 없었을 뿐이다.
자동 저장은 그대로 두고 그 위에 버튼과 상태 표시를 얹는다 —
자동 저장을 걷어내면 작성 중 이탈에 내용이 날아간다.

## 뒤집는 규칙

### 1. "최상위 폴더는 공개할 수 없다" → 허용

코드에 명시적 가드가 있었다.

```
// 루트를 공개하면 모임의 모든 사진이 링크 하나로 나간다. 공유 단위는 항상 하위 폴더다.
if (body.data.pub && target.parent_id === null) throw badRequest(…)
```

이 가드가 막던 사고(**링크 하나로 모임 사진 전부가 나가고, 되돌려도 이미 본 사람은 봤다**)는
그대로 남는다. 그래서 허용하되 **범위를 매번 명시적으로 고르게** 만든다.
"하위 포함"을 기본값으로 두지 않는다.

### 2. "하위·다른 폴더 이동 불가" → 묶음 안에서만 이동 가능

뷰어가 여러 폴더를 보게 되면 그 사이를 오갈 수밖에 없다.
규칙을 **"고른 것 밖으로는 못 간다"** 로 다시 쓴다.
묶음에 없는 폴더는 뷰어의 목록에 **나타나지도 않는다** — 존재를 알리지 않는다.

### 안 바뀌는 것

- 밖으로 나가는 것은 **미디어뿐**이다. 문서·정산·일정은 묶음으로도 나가지 않는다.
- Drive 파일 링크·서명 URL·`storage_key`·`drive_folder_id` 를 응답에 담지 않는다.
- 토큰을 폴더 id 나 묶음 id 에서 **파생시키지 않는다.**
- 중지하면 그 링크는 즉시 죽는다.

## 공유를 폴더에서 묶음으로 옮긴 이유

공유가 폴더 행에 붙어 있었다 (`folders.pub` + `folders.share_token`).
한 쌍뿐이라 **링크 하나 = 폴더 하나**가 구조적으로 강제됐고,
"최상위 + 고른 하위 폴더들"을 한 링크로 여는 게 불가능했다.

대안 세 가지를 놓고 골랐다.

| 안 | 왜 안 골랐나 |
|---|---|
| 폴더에 `share_scope('self'\|'tree')` 컬럼만 추가 | "1일차와 3일차만" 같은 **부분집합을 못 고른다.** 사용자가 명시적으로 요구한 것이다 |
| 묶음을 추가하고 폴더 토글도 유지 | **권한 규칙이 두 군데**가 된다. 언젠가 한쪽만 고쳐서 새어 나간다 |
| **묶음으로 통일** ← 채택 | 개념이 하나다. 폴더의 "공유" 버튼은 입구로 남기고, 누르면 그 폴더 하나짜리 묶음을 연다 |

기존 공개 폴더 2개는 **토큰을 그대로 물려받은 묶음으로 이관**했다
(`003_share_links.sql`). 이미 뿌려 둔 링크가 죽지 않는다.
옛 주소 `/{gid}/view/{slug}?t=` 도 호환 라우트로 살려 둔다.

### 되돌리는 비용

크다. 마이그레이션 `003` 이 `folders.pub`/`share_token` 을 **삭제**하므로
되돌리려면 역마이그레이션을 쓰고 묶음을 폴더별로 쪼개야 한다.
부분집합 묶음은 쪼갤 수가 없어서 정보가 손실된다.
그래서 이 결정만은 사용자 승인을 명시적으로 받고 진행했다.

## 사용자가 고른 것

| 물음 | 답 |
|---|---|
| 공유를 무엇에 붙이나 | **독립된 묶음.** 한 모임에 용도별로 여러 개 |
| 뷰어가 여러 폴더를 어떻게 보이나 | **묶음 안에서만 탐색 허용** |
| 공유한 뒤 새로 만든 하위 폴더는 | **자동으로 따라 나간다** |
| 묶음에서 폴더를 빼면 | **그 폴더만 빠지고 링크는 산다** |
| 여러 날 숙소 표시 | 칩을 키운다 (`숙박 중 · 3박째`) |
| 종료 시각 범위 | **모든 항목.** 숙소는 체크인/체크아웃에도 시각 |
| "미디어 임포트" 의 뜻 | 폴더 간 **파일 이동** + **폴더 자체 이동**. Drive 스캔 임포트는 범위 밖 |
| 멤버가 폴더 링크를 열면 | **배너 + "앱에서 열기".** 자동 이동은 안 한다 |

### 자동 포함에 붙인 안전장치

"새 하위 폴더가 자동으로 따라 나간다"는 편한 대신 모르고 새는 경로를 만든다.
그래서 공유 화면에 **어느 항목이 `이 폴더만` 이고 어느 항목이 `하위 전부` 인지 항상 보이게** 하고,
자동으로 들어온 폴더에는 배지를 붙인다. 규칙은 그대로 두고 눈에만 띄게 한 것이다.

### 멤버를 자동 이동시키지 않는 이유

정산 공유 링크는 멤버가 열면 앱으로 자동 이동한다. 폴더 링크는 그러지 않는다.
**방장이 "외부인에게 뭐가 보이는지" 확인하려고 일부러 여는 경우**가 있기 때문이다.
자동 이동시키면 그 확인을 할 방법이 로그아웃밖에 없어진다.

## 종료 시각을 컬럼으로 얹은 이유

`check_in`/`check_out` 을 `timestamptz` 로 바꾸지 않고 **`date` 로 두고 시각 컬럼을 따로 뒀다.**
`staysOn()` 의 날짜 문자열 비교에 숙소 칩 계산이 전부 걸려 있어서,
타입을 바꾸면 일차·숙박 로직이 통째로 흔들린다. 얻는 것에 비해 위험이 크다.

**자정을 넘기는 일정**(야간 비행·버스, `23:00 → 01:30`)은 도착 날짜 컬럼을 따로 두는 대신
**"종료가 시작보다 이르면 익일"** 이라는 규칙 하나로 덮는다.
하루를 넘기는 일정은 있어도 이틀을 넘기는 일정은 없다.
`crossesMidnight()` 이 이 판정을 하고 화면은 `+1일` 배지를 붙인다.

시각은 **표시용이고 정산에 아무 영향이 없다.** 환율 스냅샷 재계산 조건도 건드리지 않았다 —
시각이 바뀌었다고 이미 굳은 환산액이 흔들리면 안 된다.

## 판단으로 정한 것 (사용자 확인 없이)

| 정한 것 | 왜 |
|---|---|
| 사진 이름을 바꾸면 **Drive 파일명도 바꾼다** | 모임 이름 → Drive 폴더명 규칙과 같다. 저장소만 옛 이름으로 남으면 대조가 안 된다 |
| 기본 통화 수정은 **방장만** | 모임 정보 수정이 이미 방장 전용이다. 여기만 열면 규칙이 깨진다 |
| 문서는 **자동 저장 유지 + 버튼·상태 표시 추가** | 자동 저장을 걷어내면 작성 중 이탈에 내용이 날아간다 |
| 생성/참여 **결과 모달은 스위처에서만** | 시작 페이지는 갈 곳이 그 모임뿐이라 한 번 더 누르게 하는 게 손해다 |
| 폴더 이동 시 **자기 자손 밑으로 금지** | 트리가 고리가 되면 탐색이 끝나지 않는다. `canMoveFolder` 가 core 에 있다 |
| 시각 검증·박 수 계산을 **core 에 둔다** | 폼 미리보기와 서버 해석이 달라지면 안 된다. 정산의 `previewSplit` 과 같은 이유 |
| `resolveShared` 를 **core 에 둔다** | 공유 모달이 "3개 폴더가 나갑니다"라고 한 것과 서버 권한 검사가 1개라도 다르면 그게 유출이다 |

## 곁다리로 고친 버그

오류 핸들러가 413 만 특별 처리하고 **나머지 Fastify 4xx 를 전부 500 으로 바꿔 내보내고 있었다.**
보낸 쪽 잘못인데 서버 잘못으로 보여서 원인을 엉뚱한 데서 찾게 된다.
4xx 는 그대로 4xx 로 넘기되 내부 메시지는 담지 않는다.
