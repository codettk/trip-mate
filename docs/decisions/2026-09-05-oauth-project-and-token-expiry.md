# 운영이 멈췄다 — 리프레시 토큰 7일 만료, 그리고 게시한 프로젝트가 우리 것이 아니었다

2026-09-05. 사용자 신고: **"구글드라이브에서 이미지들을 못가져오는 거 같아"**

맞았다. 운영 서버 상태가 이미 답을 말하고 있었다.

```
{"ok":true,"authMode":"kakao","storage":{"driver":"gdrive","healthy":false}}
```

토큰을 직접 갱신해 보니 원인이 하나로 좁혀졌다.

```
POST https://oauth2.googleapis.com/token  →  400
{ "error": "invalid_grant",
  "error_description": "Token has been expired or revoked." }
```

**코드 결함이 아니다.** `2026-08-22-kakao-and-drive-live.md` 의 **구멍 2**(테스트 중 = 리프레시 토큰 7일)가
예정대로 터진 것이다. 마지막 재승인이 8월 22일, 사고가 9월 5일 — 14일째다.

## 썸네일 작업과 무관하다

썸네일이 실패하면 원본으로 되돌아가게 해 뒀는데(`2026-08-23-thumbnails.md`),
**그 원본도 같은 토큰을 쓴다.** 그래서 사진 한 장마다 Drive 호출 두 번이 연달아 실패했다.
되돌아가기 설계가 문제를 가린 게 아니라, 애초에 되돌아갈 곳이 없었다.

## 진짜로 놀란 것 — 게시한 프로젝트에 클라이언트가 없었다

사용자가 그 사이 **`withTripMate`** 라는 Google Cloud 프로젝트를 만들어 로고까지 넣고
**프로덕션으로 게시**해 뒀다. 그러면 7일 만료가 사라졌어야 한다. 그런데 토큰은 죽었다.

새 토큰으로 `files.list` 를 불러 봤더니 이런 게 섞여 나왔다.

```
_cms · 멍곰이 시리즈 · 엄마폴더 · 2026년 7월 14일 · shared-media
```

**TripMate 는 이런 폴더를 만들지 않는다.** `drive.file` 권한은 프로젝트 단위로 묶이므로,
우리 클라이언트가 CMS 와 같은 프로젝트에 있다는 뜻이다. 확인해 보니 그대로였다.

| | |
|---|---|
| 게시한 프로젝트 | `withTripMate` — **OAuth 클라이언트 0개** |
| 실제로 쓰는 클라이언트 | `263038991165-7q9a…` (데스크톱, 2026.7.13) |
| 그 클라이언트가 있는 프로젝트 | **`shared-media`** (CMS 와 공용) |

**빈 프로젝트를 게시한 것이다.** 우리 토큰에는 아무 효과가 없었다.

> OAuth 클라이언트 ID 의 앞 숫자가 곧 **프로젝트 번호**다. `263038991165` 를 그대로
> `?project=` 에 넣으면 진짜 프로젝트가 열린다. 이 사실이 진단을 5분으로 줄였다.

## `shared-media` 는 이미 프로덕션이었다 — 시점이 문제였다

사고 당일 확인하니 `shared-media` 의 게시 상태는 **프로덕션**이었다. 그런데 토큰은 죽었다.
모순이 아니다. **7일 시계는 토큰을 발급받은 시점의 게시 상태로 정해진다.**

| | |
|---|---|
| 8/22 토큰 발급 | 그때는 **테스트 중** → 7일 시계가 붙었다 → 8/29~9/5 사이 사망 |
| 그 뒤 어느 시점 | 사용자가 프로덕션으로 게시 |
| 9/5 토큰 재발급 | **프로덕션 상태에서 받았다** → 만료 없음 |

**게시만으로는 이미 나가 있는 토큰이 구제되지 않는다.** 게시 → 재발급 순서를 지켜야 한다.
이번에 복구하면서 재발급을 했으므로 결과적으로 순서가 맞았다.

### 이건 오늘 증명할 수 없다

게시 상태를 읽는 API 는 `drive.file` 권한으로 열리지 않고, 7일 시계는 시간이 지나야 드러난다.
**9월 12일에 `/api/health` 가 여전히 `healthy: true` 면 무기한이 맞다.** 그날까지는 가설이다.

## 그래도 `withTripMate` 로 옮기지 않는다

이름도 로고도 `withTripMate` 가 제대로 돼 있어서 그쪽으로 옮기고 싶어진다. **지금은 안 된다.**

`drive.file` 은 "이 앱이 만든 파일만"이다. `withTripMate` 에서 클라이언트를 새로 만들어 갈아 끼우면
**그 클라이언트는 기존 사진에 대한 접근권이 0** 이다. 지금 올라간 사진이 전부 404 가 된다.
드라이버 전환(구멍 3)과 같은 종류의 사고이고, 이번엔 데이터가 훨씬 많다.

**클라이언트가 실제로 사는 프로젝트는 `shared-media` 다.** 게시도 브랜딩도 거기서 해야 한다.
브랜딩 URL 은 이미 채워져 있다 (둘 다 살아 있는 것을 확인했다).

```
홈페이지   https://tripmate.nicehorang.workers.dev/          200
개인정보   https://tripmate.nicehorang.workers.dev/privacy   200   (/privacy.html 은 307)
```

**부작용:** `shared-media` 가 프로덕션이면 CMS 쪽 동의 화면도 같이 프로덕션이다.
같은 프로젝트라 분리할 수 없다. 앱 이름도 공용이라 지금은 `미디어 공유` 로 보인다.

### 인증(verification)은 토큰 수명과 무관하다

콘솔이 "앱을 인증해야 합니다" 배너를 띄우지만 **이건 게시나 토큰 만료와 상관없다.**
`drive.file` 은 민감 스코프가 아니라 심사가 면제된다. 배너가 뜬 이유는 **로고를 올렸기 때문**이다 —
로고를 쓰려면 브랜딩 심사를 통과해야 하고, 그 심사가 두 가지를 지적한다:

1. `nicehorang.workers.dev` 소유권 미확인 — `workers.dev` 는 Cloudflare 공용 도메인이라 까다롭다
2. 앱 이름(`미디어 공유`)이 홈페이지의 이름과 불일치

**둘 다 지금 풀지 않는다.** 로고를 빼면 배너가 사라지고, 동의 화면은 운영자 본인만 보므로 실사용에 지장이 없다.
자체 도메인을 붙일 때 같이 처리하는 게 싸다.

### 뒤집는 비용

- `withTripMate` 로 진짜 옮기려면 **사진 마이그레이션**이 필요하다 —
  새 클라이언트로 전부 다시 올리고 `photos.storage_key` 를 갈아야 한다. 구멍 3 과 같은 작업이다.
- 그때까지 `withTripMate` 프로젝트는 비워 둔 채로 둔다. 지우지 않는다.

## 복구 절차 (이번에 실제로 한 것)

1. `node .data/tmp/drive-reauth.mjs` — 사용자가 브라우저에서 승인, 새 리프레시 토큰 발급
2. 검증 — 토큰 갱신 200 · `about.get` 200 · 원본 319KB · 썸네일 s400 54KB
3. 로컬 `.env` 교체 (이전 값 `.env.bak`)
4. `GoogleDriveAdapter.healthy()` 를 로컬에서 직접 호출 → `true` (680ms)
5. Render API 로 `GOOGLE_REFRESH_TOKEN` 교체 + 재배포 → 약 3분 뒤 `healthy: true`

`GOOGLE_DRIVE_ROOT_FOLDER_ID` 를 `files.get` 하면 **404 가 정상이다.**
루트 폴더는 사용자가 Drive 에서 손으로 만든 것이라 `drive.file` 로는 메타데이터를 읽을 수 없다.
그 밑에 자식을 만드는 것은 된다(모임 폴더가 실제로 거기 달려 있다). 진단할 때 이걸 장애로 오해하지 말 것.

## 조용히 깨지던 것을 고쳤다

Drive 가 죽어도 화면에는 깨진 이미지만 떴다. **사용자가 눈으로 발견해서 신고할 때까지 아무도 몰랐다.**
`/api/health` 가 이미 `storage.healthy` 를 내보내고 있었으므로 그것을 읽어 띠를 띄운다
(`apps/web/src/components/StorageBanner.tsx`).

- **사진 화면과 외부 뷰어 양쪽에 붙인다.** 밖에서 보는 사람은 물어볼 데가 없어서 오히려 더 급하다.
- **첫 문장은 "사라진 것이 아니다"** 다. 사진이 안 보이면 "지웠나?" 가 첫 반응이다.
- **원인을 화면에 쓰지 않는다.** 토큰·Drive·권한 같은 서버 사정은 외부 뷰어도 읽게 되고,
  사용자가 할 수 있는 일도 아니다. "지금 안 된다"와 "누구에게 알려라"까지만 말한다.
  테스트가 `/토큰|Drive|OAuth/` 가 화면에 없음을 확인한다.
- 정상일 때는 **감싸는 상자까지 안 그린다.** 빈 div 를 남기면 여백만큼 레이아웃이 밀린다.
- 새 CSS 를 만들지 않았다 — 기존 `.tip.warn` 이다. 아이콘만 `alert` 를 더했다.

프로토타입에는 넣지 않았다. `prototype/index.html` 은 서버가 없어 저장소 장애라는 상태 자체가
존재하지 않는다 — 넣으면 늘 켜져 있거나 늘 꺼져 있는 가짜 띠가 된다.
