## 내가 정한 것

### 1. 모노레포 = npm workspaces

pnpm이 로컬에 설치돼 있지 않다. corepack으로 끌어오면 되지만, 사용자가 최종 테스트만 하겠다고 했으므로
**추가 설치 없이 `npm install` 한 번으로 끝나는 쪽**을 골랐다.

```
apps/api  apps/web  packages/core
```

`packages/core`가 존재하는 이유는 하나다 — **정산 알고리즘을 서버와 브라우저가 같은 코드로 돌리기 위해서.**
프론트에서 "지금 이 금액이면 1인 몫이 얼마"를 즉시 보여줘야 하는데(모달 안에서 계산),
그 계산이 서버 결과와 1원이라도 다르면 안 된다. 두 벌 구현을 금지한다.

### 2. DB 접근 = Kysely + pg + 순수 SQL 마이그레이션 (Prisma 아님)

- Prisma는 `prisma generate` 시 쿼리 엔진 바이너리를 내려받는다. Docker 이미지 빌드와 오프라인 재현성이 나빠진다.
- Kysely는 **런타임 코드 생성이 없고**, `apps/api/src/db/types.ts`의 손으로 쓴 `Database` 인터페이스로 컴파일 타임 타입 안전을 준다.
- 마이그레이션은 `apps/api/src/db/migrations/*.sql` 평문 + 60줄짜리 러너(`migrate.ts`). 리뷰가 쉽다.

**트레이드오프:** 스키마를 바꾸면 SQL과 `types.ts`를 **둘 다** 고쳐야 한다. 잊으면 컴파일이 깨지므로 조용히 틀리진 않는다.

### 3. 서버 = Fastify 5

Express보다 스키마 검증(zod)·타입 통합이 낫고 의존성이 적다. 라우트는 도메인별 플러그인으로 자른다.

### 4. 프론트 = Vite + React 19 + TanStack Query + React Router

- 상태관리 라이브러리를 따로 두지 않는다. 서버 상태는 전부 TanStack Query, 화면 상태는 `useState`.
- **UI 프레임워크(MUI/Tailwind 등)를 쓰지 않는다.** 프로토타입의 디자인 토큰이 이미 확정돼 있고,
  프레임워크를 끼우면 그 토큰을 덮어쓰느라 더 오래 걸린다. `styles/tokens.css` + 컴포넌트별 CSS Module로 간다.

### 5. 인증 = 카카오 OAuth + 서버 세션 쿠키

- 사용자 결정대로 **카카오 하나만**. 이메일·구글 로그인을 만들지 않는다.
- JWT가 아니라 **DB 세션 + httpOnly 쿠키**다. 초대·탈퇴·강제 로그아웃을 서버에서 즉시 끊어야 하기 때문.
- **개발용 목 로그인(`AUTH_MODE=mock`)을 둔다.** 카카오 앱 키 없이도 전체 기능을 테스트할 수 있어야 한다.
  운영에서는 `AUTH_MODE=kakao`. 목 로그인은 `NODE_ENV=production`에서 부팅 시 거부한다.

### 6. 저장소 = 어댑터 뒤에 숨긴다

```ts
interface StorageAdapter {
  createFolder(name, parentId): Promise<string>
  renameFolder(id, name): Promise<void>
  upload(parentId, file): Promise<{fileId, ...}>
  stream(fileId): Promise<Readable>   // ← 서버가 받아서 전달. 서명 URL을 브라우저에 주지 않는다.
  delete(fileId): Promise<void>
}
```

- `LocalStorageAdapter` — 개발/테스트용. `.data/storage/` 아래 실제 파일로 저장.
- `GoogleDriveAdapter` — OAuth 클라이언트 시크릿 + 리프레시 토큰. **사용자가 나중에 키만 넣으면 켜진다.**
  `STORAGE_DRIVER=local|gdrive` 환경변수로 스위치.
- 이미지는 **항상** `/api/media/:photoId` 를 통해 나간다. Drive 파일 링크·서명 URL은 어떤 경로로도 브라우저에 노출하지 않는다.

### 7. 환율 = 스냅샷 테이블 + 시드된 마감 환율

"어느 API를 쓸지"는 여전히 미정이다. 그래서 **경계를 먼저 만들었다**:

- `fx_rate(date, currency, rate)` 테이블이 정본이다.
- `RateProvider` 인터페이스: `getClosing(date, cur)`. 구현은 지금 `SeededRateProvider`(프로토타입의 `RATE_BASE`×`DRIFT`).
  나중에 실제 API 어댑터를 하나 더 끼우면 된다.
- 항목 저장 시 그날 환율을 `items.rate`에 **스냅샷**한다. 표가 갱신돼도 이미 정산된 금액이 흔들리지 않는다.

### 8. 금액 컬럼 타입 = `BIGINT`(원) / `NUMERIC(18,4)`(외화·환율)

원화는 정수여야 한다는 게 확정 규칙이라 부동소수를 아예 못 넣게 한다.
외화 입력액(`items.cost`)과 환율(`items.rate`)만 `NUMERIC`이고, 이 둘의 곱을 반올림한 `krw`는 계산 시점에 정수로 떨어진다.

### 9. 실시간 동기화 = 지금은 안 만든다

여러 명이 동시에 일정을 고치는 상황을 소켓으로 맞추는 건 범위 밖이다.
대신 TanStack Query의 `invalidate` + 15초 `refetchInterval`(정산 화면만)으로 충분히 따라간다.
**기록만 하고 넘어간다** — 나중에 SSE 한 줄로 붙일 수 있게 뮤테이션마다 `groupId`를 키로 갖게 해뒀다.

### 10. 테스트 = Vitest 한 벌

- `packages/core` — 정산 알고리즘 속성 테스트(**잔액 합 0 · 이체 합 일치 · 전부 정수**)를 랜덤 1000케이스로 돌린다.
- `apps/api` — 실제 Postgres(도커)에 붙는 통합 테스트. 목 DB를 쓰지 않는다. 라우트 단위로 시나리오를 태운다.
- `apps/web` — 타입체크 + 빌드 + 핵심 컴포넌트 렌더 테스트. E2E는 사용자 최종 테스트에 맡긴다.

## 구현하면서 추가로 정한 것

앞의 표가 "시작 전에 정한 것"이라면, 아래는 **코드를 쓰다가 마주쳐서 그 자리에서 판단한 것**이다.
전부 사용자 확인 없이 진행했고, 근거는 각 파일 주석에도 남아 있다.

### 서버

| 무엇 | 판단 | 왜 |
|---|---|---|
| **항목 본문의 필수 필드** | 일차·카테고리·제목 셋만 필수. 나머지는 서버가 기본값을 채운다 | 일정만 빠르게 추가하는 경우가 가장 흔한데, 빈 문자열과 `false` 를 폼이 일일이 실어 보내게 할 이유가 없다 |
| **환율 재스냅샷 조건** | 통화·일차가 바뀔 때 **더하기** `split` 이 꺼짐→켜짐일 때 | `split:false` 상태의 `rate` 는 스냅샷이 아니라 강제로 넣은 `1` 이다. 모임 기본 통화가 VND 인데 토글만 켜면 rate=1 이 살아남아 환산이 통째로 틀린다 |
| **숙소 날짜** | 체크인·체크아웃은 **둘 다 있거나 둘 다 없거나** | 한쪽만 있으면 `nightsOf` 는 0, `staysOn` 은 그 항목을 무시해서 조용히 사라진다. 명시적으로 거부하는 쪽이 낫다 |
| **소수 자릿수 검증** | `1e-6` 여유를 둔다 | `120.1 * 100 = 12010.000000000002` 이라 정수 판정을 그대로 하면 정상 USD 입력이 거부된다 |
| **이체 `done` 전이** | 받는 사람은 현재 상태가 `null` 이어도 완료 처리할 수 있다 | 이미 입금받았는데 보낸 쪽이 "송금 확인 요청"을 안 누르면 마감이 영원히 안 된다 |
| **이체 목록이 달라졌을 때** | 없는 (from,to) 쌍에 상태를 쓰려 하면 409 | 금액이 바뀌어 이체 목록이 재계산됐다는 뜻이다. 조용히 무시하면 사용자가 누른 게 사라진 것처럼 보인다 |
| **정산 마감 자동 해제** | 항목을 만들거나 고치거나 지우면 `settle_closed_at` 을 NULL 로 되돌린다 | 마감은 계산 결과이지 사람이 누르는 버튼이 아니다. 금액이 바뀌었는데 마감이 남아 있으면 거짓말이다 |
| **모임 수정 순서** | `syncDays` 를 `groups` 행 갱신보다 **먼저** 돌린다 | 빠지는 날짜에 일정이 남아 409 로 멈출 때, 기간만 바뀌어 있으면 화면과 DB 가 어긋난다 |
| **`dest` 를 바꿔도 `cur` 은 안 바꾼다** | `cur` 은 명시적으로 보낼 때만 | 이미 저장된 항목의 통화가 흔들리면 안 된다 |
| **초대 코드 상태 코드** | 만료·취소는 410, **없는 코드는 404** | 위조 코드와 만료 코드를 프론트가 갈라서 안내할 수 있어야 한다 |
| **재합류** | 나갔던 사람이 다시 들어오면 `left_at` 을 NULL 로 되돌린다 (행을 새로 만들지 않는다) | 정산 이력이 그 멤버 id 에 묶여 있다. 새 행을 만들면 과거 지출과 끊긴다 |
| **재합류 시 이름** | 갱신하지 않는다 | `members.name` 은 합류 시점 스냅샷이다 |
| **방장 탈퇴** | 위임하지 않으면 409. 마지막 1인이면 "모임 삭제만 가능" | 주인 없는 모임을 만들지 않는다 |
| **루트 폴더 공개** | 400 으로 거부 | 루트를 공개하면 모임의 사진 전부가 링크 하나로 나간다 |
| **사진 든 폴더 삭제** | `?force=true` 없이는 409 + 몇 장인지 | 조용히 지우면 안 된다 |
| **문서 블록 편집이 `version` 을 올리는가** | 안 올린다. `updated_at` 만 갱신 | 블록 편집이 남의 제목 저장을 409 로 튕기면 같이 못 쓴다 |
| **`settle` 블록 content** | 항상 `{}`. 비어 있지 않으면 거부 | 정산 수치를 문서에 복사해 굳히면 결제자·대상이 바뀐 뒤 문서만 옛 금액을 든다 |
| **시드의 사진** | photos 행을 넣지 않는다 (폴더만 만든다) | 실물 파일 없이 행만 있으면 깨진 썸네일이 보인다 |
| **뷰어 실패 응답** | 전부 404 (403 을 쓰지 않는다) | 403 은 "그 폴더가 존재한다"를 알려주는 셈이다 |
| **뷰어의 미지정·대상없음 목록** | 내보내지 않는다 | 항목 제목이 곧 일정 유출이다 |

### 프론트

| 무엇 | 판단 | 왜 |
|---|---|---|
| **사이드바 정산 배지** | `totalSteps - doneCount` (이체 + 기타 인원 수령 확인) | 이체만 세면 "0인데 정산이 안 끝난" 상태가 생긴다 |
| **개수 0은 비워 둔다** | 로딩 중과 "정말 0" 을 둘 다 빈칸으로 | 0을 찍으면 아직 안 불러온 상태와 구분이 안 된다 |
| **환율 미도착 시** | 폴백 환율로 숫자를 만들지 않고 미리보기를 감춘다 | 틀린 금액을 잠깐이라도 보여주지 않는다 |
| **숙소의 연결 일차** | `cat==="stay"` 면 일차 select 를 잠그고 체크인 날짜에서 도출 | 숙소는 체크인한 날에 놓인다 |
| **"실제 결제액 − 정산 반영액" 설명** | 기타 인원 몫 + 대상 없는 항목 + 반올림 셋으로 나눠 문장을 만든다 | 차이는 기타 인원 몫만이 아니다. `noTarget` 항목도 `spent` 에는 들어가고 `paid` 에는 안 들어간다 |
| **"기타 인원 N명" 합계 표기** | 쓰지 않는다. 대신 **건수**를 센다 | 항목마다 guests 가 달라 합치면 같은 사람을 여러 번 센다 |
| **뷰어의 음수 잔액** | 절댓값 + "받을 돈 / 보낼 돈" 문구 | `₩ -230,644` 는 읽기 어렵다 |
| **폼 초기화 타이밍** | 모달을 열 때 한 번만 | 쿼리 refetch(창 포커스 복귀 등)마다 리셋되면 입력이 날아간다 |
| **`next` 리다이렉트** | `/` 로 시작하고 `//` 가 아닌 값만 인정 | 오픈 리다이렉트 차단 |
| **도커 전체 스택의 `NODE_ENV`** | `.env` 값을 따르고 기본은 `production` | 목 로그인으로 전체 스택을 테스트하려면 `development` 가 필요한데, "운영에서 목 로그인 거부" 가드는 그대로 둬야 한다 |
